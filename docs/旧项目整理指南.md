## 二、三个项目的处理方案（按优先级）

### 🥇 情况 A：能找到代码 → 整理后上传

对**每一个**项目，按这 5 步走：

```powershell
# 1. 建一个干净目录（不要在原来的乱目录里直接 init）
mkdir D:\code\old-projects\library-system
# 2. 只把源码复制进去（不要 .idea、__pycache__、venv、导出的 exe）
# 3. 初始化仓库
cd D:\code\old-projects\library-system
git init
```

4. **写 `.gitignore`**（Python 模板）：
```gitignore
__pycache__/
*.py[cod]
.venv/
venv/
.idea/
.vscode/
*.exe
*.log
.env
*.db
*.sqlite3
```

5. **写 `README.md`**（面试官只看这个！必须有）：
```markdown
# 图书馆管理系统

## 项目简介
用 Python 实现图书与读者的增删改查、借还书登记与数据持久化存储。
课程设计作业，独立完成。

## 功能
- 用户管理：注册、登录、权限区分（管理员 / 普通用户）
- 图书管理：新增、查询、修改、删除
- 借还书：借书登记、归还、超期判断
- 数据存储：SQLite / JSON 文件持久化

## 技术栈
Python 3.x · 面向对象编程 · SQLite / JSON · 命令行交互界面

## 如何运行
```bash
python main.py
```

## 我负责的部分
全部代码（独立完成）

## 目录结构
（列出主要文件的作用）
```

6. **⚠️ 上传前必须做安全体检**（这一步最重要）：
```powershell
# 搜 API Key、密码、token、手机号
git grep -n -I -E "api[_-]?key|password|passwd|secret|token|sk-[A-Za-z0-9]{16,}"
```
**搜到任何真实的值 → 立刻删掉，改成从 `.env` 或环境变量读取**，然后再提交。

7. 提交并推送：
```powershell
git add -A
git commit -m "feat: 初始化项目"
& "$env:LOCALAPPDATA\Programs\gh\bin\gh.exe" repo create library-system --public --source=. --push
```

### 🥈 情况 B：代码找不到了 → **不要硬编，两个选择**

#### 选择 1（推荐）：**重写一个精简版**
- 时间：**半天到 1 天**，不是一周
- 理由：这类管理系统对现在的你来说是"练手题"。重写一遍你反而能讲清楚细节（面试必问"这个表怎么设计的"）。
- 重写时**直接按现代做法写**：用 FastAPI + SQLite + Pydantic，而不是 `input()` 循环。这样一个项目就同时体现"Python 后端能力"，比原来那个更有说服力。
- 仓库名建议：`library-management-api`

#### 选择 2：**从简历里删掉**
- 如果第 1-6 周的 fitness-ai 做扎实了，**这一个项目就够撑起简历**，没必要放凑数的课程设计。
- "删掉"比"留着但答不上来"安全得多。面试官问"这个项目你印象最深的难点是什么"，你答"就是普通的增删改查"——这一轮就废了。

**把 fitness-ai 的「AI 周报」功能顺便做成一个独立的 AI 问答小项目（3 天足够）**：

```markdown
# ai-qa-web —— 基于大模型的问答网页

## 项目简介
网页版 AI 问答系统，支持与"虚拟老师"多轮对话，回答以流式方式逐字输出。

## 技术栈
前端：原生 HTML + JavaScript（fetch + SSE）
后端：Python 3.12 + FastAPI（StreamingResponse）
大模型：DeepSeek API / 通义千问 API（OpenAI 兼容格式）
配置：python-dotenv 从 .env 读取 API Key

## 核心实现
1. 后端 /api/chat/stream 接口，用 StreamingResponse 逐块转发模型输出
2. 前端用 fetch + ReadableStream 接收，实现打字机效果
3. 多轮对话：对话历史存 Redis，只保留最近 10 轮
4. API Key 只存在服务端 .env，前端拿不到（安全设计）
```

**这个重做版比原来的强**，因为你能讲清楚：流式输出原理（SSE）、多轮上下文怎么管、Key 为什么不能放前端。
